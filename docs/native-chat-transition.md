# Native chat transition

The cumulative release now routes /buyer/chat to /buyer/messages and /supplier/messages to /supplier/marketplace-chat. Product chat continues to create native product-bound threads. Seller navigation no longer polls legacy unread counts or labels chat as SMS. Native inbox unread state remains in its own workspace.

The old Chatwoot send/quote components are removed. /chat-history is an authenticated participant-only, paginated text archive. It selects only thread identifiers/timestamps and message text/timestamps, renders escaped text without HTML or contact links, and performs no writes or provider requests. Existing historical text is not retroactively contact-filtered. Attachments and separate legacy quote/inquiry records are preserved in storage but not presented as native proposals or executable checkout. Missing or unauthorized threads return 404. No admin-wide chat access is added.

No schema change or data migration. Native chat remains text-only with polling; calls are disabled. This is not an omnichannel support replacement. External NestJS endpoints, Chatwoot accounts/webhooks and Redis services are unchanged and may still receive external traffic. The new UI does not secure or shut down those endpoints.

Before retiring services: deploy and verify the native release; preserve old database/attachments and queue evidence; identify all Redis/Chatwoot consumers, support inboxes and domains; disable legacy external ingress in a separately approved operational change; monitor for dependencies; retire only identified services reversibly. The currently deployed old application still uses Chatwoot and must not lose its backend prematurely. Never delete shared Redis volumes based only on this source change.
