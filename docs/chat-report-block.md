# Participant safety and older proposals

Each authenticated participant can block new messages and proposals in a specific product conversation. A block belongs to its creator: unblocking never removes the other participant's block. Server checks enforce this, including concurrent block/send transactions; exact retries of previously persisted writes still return their original result. History, ordinary order/dispute access and review/acceptance of existing proposals remain available. This is a conversation block, not an account-wide ban across every product. No service or external channel is blocked by this code.

Participants can report CONTACT, HARASSMENT, PAYMENT or OTHER. A new report freezes at most10recent messages from that conversation; it copies no profile phone/email, attachments or unrelated threads. Fixed reason choices avoid a new unvalidated free-text surface. Reports deduplicate while OPEN, retries bind request ID/author/thread/reason, and each account is limited to10new reports/day. A new request after review can create another case; previous evidence remains intact. Reporting is not an order dispute or emergency service, and it sends no external notification.

/admin/chat-reports lists minimal case metadata; detail shows only the report snapshot and review history. Access requires the current database ADMIN role. Review decisions FOLLOW_UP or NO_ACTION are recorded atomically with actor/time events; retry/concurrent review records one decision. REVIEWED means reviewed, not automatically resolved: no suspension, unblock, refund, payment, notification or other sanction is performed. Follow-up requires an operator. Evidence is retained; no automatic retention deletion is configured.

Proposal history now links older OPEN proposals into their original participant-scoped inbox. Loading validates both proposal ID and thread; review and explicit acceptance reuse existing price/stock/address/fingerprint/idempotency safeguards. Neither report nor block changes payment verification or makes messages payment proof. Cancelled or invalid proposals remain unexecutable.
